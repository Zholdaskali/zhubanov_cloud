# MERN CLOUD — полный курс, уроки 1–26

Учебное облачное хранилище на MongoDB, Express, React и Node.js с оформлением
Zhubanov University. Проект продолжен с локального состояния урока 11 до
финальных функций курса Ulbi TV.

[Плейлист из 26 видео](https://www.youtube.com/playlist?list=PL6DxKON1uLOGd4E6kG6d5K-tsTFj-Deln)
· [Исходный проект автора](https://github.com/utimur/MERN-cloud-disk)

## Запуск локально

Нужны Node.js 22.12+ и MongoDB либо Docker Desktop.

```sh
npm ci --prefix server
npm ci --prefix client
docker compose up -d
```

В двух терминалах из корня проекта:

```sh
npm run dev --prefix server
```

```sh
npm start --prefix client
```

Откройте http://localhost:3000, зарегистрируйтесь и войдите.
API работает на http://localhost:5001. Учебное ограничение пароля: 3–12 символов.

## Что работает

- Регистрация, вход с JWT, восстановление сессии.
- Создание вложенных папок, вход в папку и возврат назад.
- Загрузка нескольких файлов через кнопку и перетаскивание в текущую папку.
- Прогресс каждого файла, отметки успешной загрузки и ошибок.
- Скачивание с исходным именем, удаление файлов и пустых папок.
- Проверка свободного места и освобождение места после удаления.
- Поиск по всему диску без учёта регистра, сортировка по имени, типу и дате.
- Список и плитка, анимация появления, форматирование размеров.
- Профиль, загрузка/замена/удаление аватара PNG, JPEG, WebP.
- Собранный клиент и API могут работать с одного домена.

Размер одного файла — до 100 МБ, аватара — до 5 МБ. Имена — до 100 символов
без разделителей пути и специальных файловых символов. Файлы другого
пользователя недоступны через API. Поиск охватывает весь личный диск;
открытие найденной папки возвращает обычный режим просмотра.

Папки удаляются после очистки содержимого, как в курсе. Существующие материалы
педагогической практики в `artifacts/` не изменялись.

## Настройки

Локальные значения находятся в `server/config/default.json`. Для переопределений
можно создать `server/config/local.json` (он исключён из архива):

```json
{
  "dbUrl": "mongodb://127.0.0.1:27017/mern_cloud",
  "secretKey": "ваш-длинный-случайный-ключ",
  "serverPort": 5001,
  "filePath": "./files",
  "staticPath": "./static"
}
```

Относительные пути хранилища считаются от папки `server` и работают на macOS,
Linux и Windows. Настройки также читаются из переменных `MONGODB_URI`,
`JWT_SECRET`, `FILE_PATH`, `STATIC_PATH`, `PORT`.
`.env.example` — образец, автоматически файл `.env` не загружается.

Адрес API клиента: `VITE_API_URL`, пример в `client/.env.example`.
По умолчанию в режиме разработки это `http://localhost:5001`.
Для одного домена укажите `VITE_API_URL=/` до сборки.

## Размещение на Render

В корне находится [render.yaml](render.yaml) для создания бесплатного веб-сервиса
Render через Blueprint. Клиент собирается и раздаётся Express с того же домена.

### Создание базы MongoDB Atlas

1. Создайте аккаунт на [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) и проект.
2. Создайте бесплатный кластер (Shared, M0). Выберите регион рядом с регионом
   будущего сервиса Render.
3. В **Database Access** создайте пользователя базы данных. Сохраните пароль —
   это не пароль от аккаунта Atlas.
4. В **Network Access** добавьте `0.0.0.0/0`. У бесплатного Render нет
   постоянного исходящего IP для ограничения доступа по адресу. Используйте
   отдельного пользователя базы с минимальными правами и надёжный пароль.
5. Нажмите **Connect → Drivers**, скопируйте URI подключения и подставьте
   пароль пользователя. Укажите базу `mern_cloud` перед `?`, например:
   `mongodb+srv://USER:PASSWORD@cluster.example.mongodb.net/mern_cloud?retryWrites=true&w=majority`.
   Если в пароле есть символы вроде `@`, `:`, `/` или `#`, их нужно
   URL-кодировать.

### Развёртывание

1. Отправьте проект в GitHub.
2. В Render выберите **New → Blueprint**, подключите репозиторий и подтвердите
   создание сервиса из `render.yaml`.
3. Когда Render запросит `MONGODB_URI`, вставьте URI из Atlas. `JWT_SECRET`
   Render сгенерирует автоматически.
4. После успешного деплоя откройте URL сервиса и зарегистрируйтесь.

Render использует `npm ci && npm run build` для сборки и `npm start` для запуска.
Клиент и API работают с одного домена.

Бесплатный сервис Render может засыпать после простоя, а его файловая система
временная. Поэтому загруженные пользователями файлы и аватары могут исчезнуть
после перезапуска или нового деплоя. Atlas сохраняет данные MongoDB, но не
файлы. Для надёжного хранения загрузок потребуется внешний файловый сервис или
платный постоянный диск и соответствующая настройка `FILE_PATH`/`STATIC_PATH`.

Локально проверить единый сервер можно так:

```sh
VITE_API_URL=/ npm run build --prefix client
npm start
```

Откройте http://localhost:5001; MongoDB должна работать. Маршрут `/profile`
открывается напрямую и после обновления страницы.

## Проверки

```sh
npm test
npm run build --prefix client
```

Тесты без БД проверяют JWT, параметры запросов, файловую систему, навигацию,
сброс состояния при выходе и защиту списка от запоздавших ответов.

Полный тест использует **отдельную тестовую MongoDB** на порту 27019 и базу
`yt_course_test`. Тест удаляет эту базу после завершения:

```sh
docker run -d --rm --name yt-course-test-mongo -p 127.0.0.1:27019:27017 mongo:7
COURSE_INTEGRATION=1 npm test --prefix server
docker stop yt-course-test-mongo
```

## Если не запускается

- Ошибка соединения с MongoDB: запустите Docker Desktop и `docker compose up -d`.
- «Нет соединения с сервером»: проверьте API на порту 5001.
- `EADDRINUSE`: порт занят другим процессом.
- Сессия истекла: войдите заново, JWT действует час.
- Файл уже существует: выберите другое имя или удалите старый файл.
- Остановка базы: `docker compose stop`; данные сохраняются в Docker volume.

Проект сохраняет React 16, Redux и Mongoose 5 из учебного курса. Учебный ключ
JWT необходимо заменить перед внешним размещением. Тема университета авторская;
монограмма JU не является официальным логотипом.
