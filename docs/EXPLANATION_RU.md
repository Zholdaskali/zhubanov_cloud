# Как устроен проект

## 1. Общая схема

Браузер показывает интерфейс React. Когда пользователь нажимает кнопку,
клиент отправляет HTTP-запрос через Axios серверу Express. Сервер проверяет
запрос, читает или меняет документы MongoDB через Mongoose и возвращает JSON.
Redux сохраняет полученный результат, а React обновляет экран.

MongoDB хранит сведения об аккаунтах и папках. Файловая система сервера хранит
сами каталоги. Это два разных хранилища: документ File описывает папку,
а `server/files/<id пользователя>/<название>` — реальный каталог.

## 2. Сервер: где что находится

| Файл | Назначение |
| --- | --- |
| `server/index.js` | Создаёт Express, подключает middleware и маршруты, соединяется с MongoDB и запускает HTTP-сервер |
| `server/config/default.json` | Порт, адрес MongoDB, ключ подписи JWT, каталог хранения |
| `server/models/User.js` | Схема аккаунта |
| `server/models/File.js` | Схема файла или папки |
| `server/routes/auth.routes.js` | Регистрация, вход, восстановление авторизации |
| `server/middleware/auth.middleware.js` | Проверка JWT до выполнения защищённого обработчика |
| `server/middleware/cors.middleware.js` | Разрешение запросов клиента с другого порта |
| `server/routes/file.routes.js` | Связывает HTTP-методы с контроллером папок |
| `server/controllers/fileController.js` | Проверяет данные, создаёт папку и получает список |
| `server/services/fileService.js` | Работает с каталогами на диске |

`User` содержит email, хеш пароля, лимит пространства, занятое место и
служебные поля. Пароль не сохраняется открытым текстом: bcrypt превращает его
в хеш. При входе сравнивается введённый пароль с хешем.

`File` содержит `name`, `type`, `size`, `path`, `date`, `user`, `parent`,
`childs`. На этом этапе используется `type: 'dir'`. Поле `user` связывает
папку с владельцем. `parent: null` означает корень диска пользователя.
Поля `parent` и `childs` подготовлены для дерева папок следующих уроков.

## 3. Регистрация

1. Пользователь вводит email и пароль в `Registration.jsx`.
2. `actions/user.js` отправляет POST `/api/auth/registration`.
3. Express Validator проверяет email и длину пароля.
4. Сервер проверяет, что email ещё не занят.
5. bcryptjs создаёт хеш, Mongoose сохраняет User.
6. FileService создаёт корневой каталог пользователя.
7. Клиент показывает сообщение. После регистрации нужно отдельно войти.

## 4. Вход и JWT

POST `/api/auth/login` ищет User по email и сравнивает пароль через bcrypt.
При успехе сервер подписывает JWT с идентификатором пользователя и временем
жизни один час. Ответ содержит `token` и сведения о пользователе без пароля.

Клиент записывает токен в localStorage и пользователя в Redux. Состояние
`isAuth` переключает маршруты: вместо формы становится доступен диск.

В защищённых запросах клиент добавляет заголовок:

```text
Authorization: Bearer <token>
```

`auth.middleware.js` проверяет подпись JWT и помещает его данные в `req.user`.
Идентификатор владельца берётся из проверенного токена, а не из тела запроса.
GET `/api/auth/auth` позволяет восстановить сессию после перезагрузки страницы.
При выходе Redux очищает пользователя и удаляет токен из localStorage.

JWT подписан, но его содержимое не является зашифрованным паролем.
Ключ подписи хранится только на сервере. localStorage выбран по учебнику;
для публичного продукта потребуется отдельная проработка хранения сессий.

## 5. Клиент и Redux

`src/index.jsx` помещает App внутрь Provider и передаёт ему Redux store.
`components/App.jsx` настраивает React Router и выбирает доступные страницы.
`Navbar.jsx` показывает ссылки на регистрацию/вход либо кнопку выхода.

В `reducers/index.js` объединяются две части состояния:

- `user`: текущий пользователь и флаг авторизации;
- `files`: массив папок, текущий каталог, видимость PopUp.

Reducer — функция, которая возвращает новое состояние для указанного action.
Например, ADD_FILE добавляет созданную папку в массив, SET_FILES заменяет
список результатом сервера. Redux Thunk позволяет action выполнять
асинхронный запрос и только затем вызывать `dispatch` обычного action.

`Disk.jsx` загружает список через `useEffect`. `FileList.jsx` перебирает массив,
а `File.jsx` рисует строку: значок, имя, дату, размер. Нулевой размер папки
на этом этапе нормален: загрузка файлов ещё не реализована.

## 6. Урок 11: создание папки и PopUp

1. «Создать папку» вызывает `setPopupDisplay('flex')`.
2. Popup читает значение из Redux и становится видимым.
3. Имя хранится в локальном `useState` компонента Popup.
4. Подтверждение вызывает thunk `createDir(currentDir, dirName)`.
5. Axios отправляет имя, `type: 'dir'` и родителя на POST `/api/files`.
6. Middleware проверяет JWT.
7. Контроллер проверяет имя, допустимость родителя и владельца.
8. FileService создаёт каталог. Контроллер сохраняет документ File в MongoDB.
9. Сервер возвращает новый документ.
10. `dispatch(addFile(...))` обновляет список; окно закрывается после успеха.

Клик по фону закрывает окно. `stopPropagation()` на внутреннем блоке не даёт
клику по полю или кнопке всплыть до фона и случайно закрыть PopUp.

## 7. API

| Метод | Адрес | Данные / результат |
| --- | --- | --- |
| POST | `/api/auth/registration` | `{email, password}` → сообщение |
| POST | `/api/auth/login` | `{email, password}` → `{token, user}` |
| GET | `/api/auth/auth` | JWT → обновлённый `{token, user}` |
| GET | `/api/files` | JWT → корневые папки текущего пользователя |
| GET | `/api/files?parent=<id>` | JWT → содержимое указанного родителя |
| POST | `/api/files` | JWT и `{name, type: 'dir', parent: null}` → документ папки |

Коды: 200 — успех, 400 — неверные данные/ошибка создания,
401 — неверный или просроченный токен, 404 — объект не найден,
500 — ошибка чтения данных. Некоторые обработчики авторизации сохранены
близко к курсу и возвращают сообщение об ошибке без корректного HTTP-кода.

## 8. Чем сборка отличается от исходника автора

За основу взят именно коммит урока 11, а не окончание всего курса.
React, Redux, компоненты и структура API сохранены.

- Create React App заменён Vite для сборки без старого Webpack/OpenSSL.
  Точка входа переименована из `index.js` в `index.jsx`.
- JWT-библиотека обновлена до версии 9 из-за несовместимости старой версии с Node.js 25.
- MongoDB настроена локально: чужой адрес Atlas убран.
- Абсолютный Windows-путь заменён переносимым `path.join`.
- Корневой каталог пользователя создаётся автоматически.
- Для даты используется `Date.now` как функция: дата вычисляется при создании
  документа, а не один раз при старте сервера.
- Добавлена проверка имён папок и принадлежности родителя пользователю.
- Ошибки сети показываются без обращения к отсутствующему `response`.
- При первом открытии без токена не выполняется лишний запрос авторизации.
- PopUp закрывается после успешного создания.
- Добавлены Docker Compose для MongoDB и русская документация.

## 9. Как проверить самостоятельно

Создайте аккаунт, войдите, добавьте папку «Учёба», обновите страницу и убедитесь,
что папка осталась. Выйдите и создайте второй аккаунт: первый каталог не должен
появиться в его списке. Попробуйте повторное имя и имя `../test`: сервер
должен отказать. Откройте вкладку Network в инструментах разработчика, чтобы
увидеть запросы, заголовок Authorization и ответы JSON.

Перезапуск сервера не удаляет документы MongoDB или реальные каталоги.
Изменение MongoDB вручную не удаляет папки на диске и наоборот. В учебном коде
операции MongoDB и файловой системы не объединены транзакцией; при сбое между
ними могут остаться несогласованные данные. Для этого этапа удобнее проверять
на отдельных учебных аккаунтах.

## 10. Как объяснить проект своими словами

«Это клиент-серверное приложение на MERN. React отображает формы и список
папок, Redux хранит состояние интерфейса. Express принимает запросы,
Mongoose работает с MongoDB. При регистрации пароль хешируется, при входе
выдаётся JWT. Запросы к папкам проходят проверку токена, поэтому пользователь
видит свои данные. Создание папки выполняется на сервере, а результат
добавляется в Redux без перезагрузки страницы».
